API endpoint
POST /api/music/playlists/create/
Request:
{
  "name": "HarmonIQ — Chill R&B",
  "description": "A playlist created from my HarmonIQ discoveries.",
  "public": false,
  "track_ids": ["spotify_track_id_1", "...", "..."]
}
name required (≤100 chars, non-blank); track_ids required, ≥1 valid ID, duplicates removed in serializer; description optional (≤300); public defaults to false.
Validation lives in the serializer: track IDs must match ^[A-Za-z0-9]{22}$ (rejects URLs/malformed IDs), empty list and blank name produce normal DRF 400s.
Response (201):
{
  "playlist": {
    "id": "...",
    "name": "...",
    "spotify_url": "https://open.spotify.com/playlist/...",
    "public": false,
    "track_count": 3
  }
}
spotify_url uses Spotify's external_urls.spotify with a constructed fallback. No raw Spotify response blobs returned.
Spotify endpoints used
- POST https://api.spotify.com/v1/me/playlists (create; body name/description/public)
- POST https://api.spotify.com/v1/playlists/{id}/items (add tracks; body uris), modern endpoint, batched at 100/per request, one call per batch — never one call per track.
Authentication behavior
permissions.IsAuthenticated (DRF session auth, unchanged CSRF/session behavior — no csrf_exempt). The connection is always request.user.spotify_connection; no account ID accepted from the client, so one user can never use another user's connection. No connection → clean 400 "Spotify not connected".
Token refresh behavior
View calls connection.get_valid_access_token(), which refreshes expired tokens through the existing SpotifyConnection.refresh_tokens() / SpotifyAuthService.refresh_access_token path. No manual refresh in the view. Refresh failure (ValueError) → clean 400.
Error handling
- Spotify 401 → 401, friendly "connection invalid or expired, reconnect" message.
- Spotify 403 → 403, "no permission to create/modify playlists, reconnect".
- Spotify 404 → 404; 429 → 429 "rate-limited"; other statuses (incl. 5xx) → 502 "try again shortly".
- Add-items failure after successful creation → _spotify_error_status(exc) with an explicit "playlist created but adding tracks failed — playlist is incomplete" error plus the playlist id (track_count 0), so partial success is never reported as full success.
- No tokens, refresh tokens, or secrets in any response; raw internal exceptions are converted to friendly messages; only Spotify's error.message string is echoed as detail.

Known limitations
- No permanent playlist model persisted in HarmonIQ DB (per spec) — the playlist lives only on Spotify and is returned in the response.
- Creating a public playlist relies on the playlist-modify-public scope granted in 6.12.1; a pre-6.12.1 connection must be reauthorized or Spotify returns 403 (surface as the friendly reconnect message).
- No idempotency/deduping against Spotify on retry (a retry after partial failure may create a second playlist); the incomplete-playlist response includes the created id so a future phase can recover explicitly.
